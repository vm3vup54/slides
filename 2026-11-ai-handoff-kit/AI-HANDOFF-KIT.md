# AI 交接簿建置包

> 版本 0.3（測試版）｜2026-11-24｜Windows、Mac 適用
> 讓 AI 在新對話、換工具、換電腦時，先讀同一本交接簿再開始工作。

```text
第一級 單機交接簿          →   第二級 多台電腦接力
一台電腦，一種或多種 AI         兩台以上電腦，一種或多種 AI
規則＋交接便條                  加上 GitHub 同步、簽到表、本機卡
（開工／換手／收工）            （開工／換手／收工）
```

**從頭到尾只有三個口令：開工、換手、收工。**第二級只是 AI 在背後多做一些事，你說的話不變。

| 口令 | 第一級 | 第二級多做 |
| :-- | :-- | :-- |
| 開工 | 讀便條，說明進度 | 先更新到另一台的最新進度，看簽到表並簽到 |
| 收工 | 確認後寫便條 | 再把工作成果上傳並簽退 |
| 換手 | 同一台電腦換新對話：確認後寫便條，給接續指令 | 進度改記在日誌，不簽退、不上傳 |

| 級別 | 適合誰 | 需要 | 大約時間 |
| :-- | :-- | :-- | :-- |
| 第一級 | 一台電腦，換對話、換 AI 都想接得上 | 能讀寫資料夾的 AI Agent（Codex、Claude Code 這類） | 10 分鐘 |
| 第二級 | 兩台以上電腦輪流用 | 第一級、Git、GitHub 帳號，且機關允許 | 40～50 分鐘 |

時間為估計。一次只做一級，通過驗收再往上；只用一台電腦的人，做完第一級就夠了。

## 給人看：先選你的情況

```text
第一次建立交接簿 → 在空資料夾從第一級開始
另一台／全新電腦 → 先下載自己的既有 repo，再接回原級別
這台已有資料夾 → 先檢查改動、更新既有資料，再接續工作
```

**換到新電腦，要先下載一次自己的資料夾；之後每天說「開工」就會自動更新。**不要在每台電腦各建一套。

公開的 `vm3vup54/slides`（`2026-11-ai-handoff-kit` 資料夾）提供本說明書；你在第二級建立的「自己的 repo」才放你的規則、交接與工作資料。接入另一台時，必須提供自己的 repo 網址。

第一台若只完成第一級，尚未建立並上傳私人 repo，要先在第一台完成第二級，另一台才有資料可以下載。

## 第一次建立：三步開始

1. 建一個新的空資料夾，用 AI Agent 開啟。一般聊天網頁不能讀寫資料夾，不適用。要做第二級，資料夾不要放在 OneDrive、Google 雲端硬碟、iCloud 等同步位置。
2. 複製下面其中一段，貼上送出。
3. 回答 AI 的問題，照它的說明完成驗收。

AI 讀不到網址時，請下載這份檔案放進資料夾，再告訴 AI「檔案已放進資料夾」。

**第一級**

```text
請完整讀取這份建置包，只執行「第一級」：
https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md

我是新手，請用繁體中文白話說明。先告訴我計畫，等我同意再建檔；已有同名檔案就停下來問我，不要覆蓋。做完帶我驗收。讀不到網址就直接告訴我，不要自行猜內容。
```

**第二級**

```text
請完整讀取這份建置包，只執行「第二級」：
https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md

先確認第一級已完成，再問我機關是否允許把這些資料放上 GitHub。安裝軟體、登入、建立儲存庫、上傳，每一項都先問我；登入由我自己操作。修改 AGENTS.md 前先備份並給我看差異，等我同意再改。讀不到網址就直接告訴我，不要自行猜內容。
```

## 新電腦：貼這段接回既有交接簿

用能讀寫檔案的 Codex 或 Claude Code，先開啟一個供接入作業使用的空資料夾（不要選家目錄、桌面根目錄、磁碟根目錄或雲端同步位置），貼上以下指令。下載完成後，依 AI 指示改開下載好的專案資料夾。

```text
請完整讀取建置包 0.3 版，執行「新電腦首次接入」：
https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md

我的既有 repo：〈自己的 GitHub repo 網址〉
讀到舊版時請我提供新版檔案。先問網址與下載位置，檢查 Git、gh 與登入；下載後請我開啟資料夾，讀規則與交接、確認 Skill 入口與本機卡，再驗收接回原級別。不要重建或自動升級；安裝、連結與推送先問我。讀不到網址就告訴我。
```

已拿到第一台產生的「新電腦接續指令」時，優先貼那段，因為其中已填好自己的 repo 網址。

新電腦接入入口從 0.3 版提供；先確認 AI 讀到的建置包版本。若線上仍是舊版，改提供這份下載檔，不自行猜新版步驟。

## 已有資料夾，但很久沒用：貼這段

在原本交接簿資料夾開啟 AI，不要另建一套：

```text
請完整讀取這份建置包，執行「已有資料夾的更新接入」：
https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md

先確認這是我原本的交接簿。檢查我這台有沒有還沒存上去的東西；能安全更新才更新，不確定就先問我，不要覆蓋，也不要重新建置。更新後重新讀規則與交接，按原本級別接續工作。
```

恢復工作脈絡是讀回「已保存且已上傳」的規則、筆記與交接，不會自動恢復所有聊天紀錄、未提交檔案、金鑰、已安裝軟體或登入狀態。

> 使用前請確認機關的資安規定。密碼、金鑰、個資與機敏資料不要交給 AI，也不要放進儲存庫。私人儲存庫仍是外部雲端服務，不等於可以放公務資料。

# 以下給 AI 執行

## 0. 執行總則

### 0.1 角色與語氣

- 你在協助一位不熟程式的使用者。全程繁體中文，術語第一次出現要用一句生活化的話解釋。
- 每一級開始前，先用三點說明：會建立或修改什麼、為什麼、怎麼復原。等使用者同意才動手。
- 一次只問一組問題，給預設值讓使用者可以說「照預設」。
- 使用者的口令只有「開工」「換手」「收工」三個，從第一級就都有。不另創口令，也不要求使用者說 Git 指令；更新與上傳一律包在開工、收工裡，由你執行。「確認」是回答你的問題，不是口令。
- 預設使用者是第一次建置。技術檢查由你處理，不要把檢查過程、指令與路徑細節全部丟給使用者；只說現在要做什麼、要他決定什麼、結果如何。需要同意、有風險或卡住時，才用白話說清楚，第 0.2 節該給看的內容仍要給。

### 0.2 授權界線

這份檔案只是操作說明，不代表使用者已同意。下列動作每次都要當下取得同意：

| 動作 | 要先讓使用者看到 |
| :-- | :-- |
| 安裝軟體 | 名稱、來源、用途 |
| 登入帳號 | 由使用者自己操作，不代填帳密或驗證碼 |
| 修改既有檔案 | 備份位置與差異 |
| 建立遠端儲存庫 | 帳號、名稱、私人或公開 |
| 提交與推送 | 完整檔案清單、掃描結果 |

唯一例外是第二級「開工只推送簽到」，須在建置時另外說明並取得同意。

### 0.3 禁止事項

- 不覆蓋、刪除、改名既有檔案，除非使用者看過差異並同意。
- 不讀取、不輸出密碼、金鑰、權杖、個資。只檢查檔名或是否存在時，也不要印出內容。
- 不使用 `git add .`、`git add -A`、`git push --force`、`git reset --hard`、`git clean`。
- 不修改 Git 全域設定，不建立公開儲存庫。
- 不順手執行下一級。只處理已確認的交接簿資料夾；第 3 節的下載目的地、第 6 節的兩個本機入口須另外取得同意，不能擴大到其他資料夾。

### 0.4 回報方式

每一級結束時列出：

- **完成**：實際做了什麼，附檔名或指令結果。
- **未驗證**：哪些還沒測，為什麼。
- **需要你做**：使用者下一步。

沒有親自確認過的事不說完成。遇到停止條件，直接說停在哪一步、看到什麼、有哪些選擇。

### 0.5 環境檢查（每一級都先做）

1. 先辨識情況：初次建立、全新電腦接既有 repo、已有資料夾更新。接既有 repo 時先執行第 3 節，不把空資料夾誤判為「必須重做第一級」。說出目前資料夾的完整路徑，請使用者確認。
2. 判斷作業系統：Windows 用 PowerShell 語法，Mac 用 zsh 語法。
3. 停止條件：
   - 目前位置是使用者家目錄、桌面根目錄或磁碟根目錄。
   - 沒有讀寫檔案的能力。此時請使用者改用 Codex 或 Claude Code 這類工具。
4. 列出目前資料夾第一層的檔名，只看檔名，不讀內容。
5. 判斷目前做到哪一級：

| 看到 | 判斷 |
| :-- | :-- |
| 沒有 AGENTS.md、HANDOFF.md | 尚未開始 |
| 兩者都有，且 AGENTS.md 有「交接規則」 | 第一級已建立 |
| 另有 Git 遠端、machines/，且 AGENTS.md 有「接力規則」 | 第二級已建立 |
| 有 Git 遠端，但 AGENTS.md 只有舊版「同步規則」 | 舊版第二級：說明差異，同意後依 2.7、2.8 補齊 |

初次建置要求的級別缺少前一級時，停下來說明，不自動補做。接入既有 repo 時，下載並讀取後再判斷原級別；檔案標題只代表候選狀態，還要詢問前次驗收是否完成，不自行宣稱已驗收。

## 1. 第一級：單機交接簿

**目標**：新對話只要說「開工」，就說得出上次進度。

### 1.1 檢查

確認 `AGENTS.md`、`CLAUDE.md`、`HANDOFF.md` 是否存在。任何一個存在就停下來，給三個選擇：

1. 保留原檔，把交接規則加在後面（先備份並顯示差異）。
2. 換一個空資料夾。
3. 先不做。

### 1.2 訪談

一次問完：

1. 你主要做什麼工作？（預設：公務文書、會議紀錄、簡報）
2. 回覆要什麼風格？（預設：繁體中文、先講結論、白話）
3. 有什麼事不能做？（預設：不刪檔、不外傳資料、不確定先問）

### 1.3 建立 AGENTS.md

`AGENTS.md` 是 AI 的員工手冊。先寫「關於我」與訪談結果，再原文寫入：

```markdown
## 交接規則

- 我說「開工」：先讀 HANDOFF.md，用三句話說明上次做到哪、下一步、要注意什麼。先不要動手，等我指示。
- 我說「收工」：列出這次改了哪些檔案（含上一則「換手」便條列的檔案），以及準備寫進便條的內容。等我說「確認」，才更新 HANDOFF.md。
- 我說「換手」：我要在同一台電腦換新對話，工作還沒結束。先停在安全點，列出做到哪、決定與理由、待確認、下一步、相關檔案與所有未完成或未提交的改動。等我說「確認」，才寫進 HANDOFF.md 並標明「換手」，再給我一段可貼到新對話的接續指令：要讀哪些檔案、未完成的改動請保留、先回報狀態再動手。不提交、不推送。
- 更新便條時，新的放最上面，舊的保留。每則寫日期時間、使用的 AI 工具、做完、下次接手、注意事項。
- 修改、刪除或覆蓋我的原始檔之前，先問我。
- 不讀取、不寫入密碼、金鑰、個資與機敏資料。
- 不確定就問我，不要自行編造進度。
```

### 1.4 建立 CLAUDE.md

內容只有一行，讓 Claude Code 讀同一份規則；Codex 直接讀 `AGENTS.md`：

```markdown
@AGENTS.md
```

```text
AGENTS.md ← Codex 直接讀
    ↑
CLAUDE.md 以 @AGENTS.md 引用同一份規則
```

`@AGENTS.md` 是檔案引用，和資料夾捷徑不同；不要複製兩份規則各自維護。新版 Claude Code 在部分設定下也可直接讀 AGENTS.md，這個引用入口可保留以相容其他環境。若原有 CLAUDE.md 另有內容，先備份、顯示合併差異，不改成只剩一行。

### 1.5 建立 HANDOFF.md

`HANDOFF.md` 是交接便條。時間用實際時間，工具填目前使用的工具：

```markdown
# 交接便條

## YYYY-MM-DD HH:MM｜<AI 工具>
- 做完：建立 AI 交接簿。
- 下次接手：等我指定第一件工作。
- 注意事項：尚未用新對話測試。
```

### 1.6 自查

- 三個檔案都讀回來，確認規則七條都在、`CLAUDE.md` 有 `@AGENTS.md` 這一行（新建的只有這一行；沿用既有檔案時保留原內容）、便條時間是真的。
- 中文沒有亂碼，檔名大小寫正確。Windows PowerShell 讀檔加 `-Encoding UTF8`，否則好的檔案也會顯示成亂碼。

### 1.7 驗收（請使用者操作）

1. 交代一件小事，例如「建立 note.txt 寫一句話」。完成後說「收工」，看過內容再說「確認」。
2. 在**同一個資料夾**開新對話，只輸入「開工」。
3. 說得出剛才的小事與下一步，才算通過。
4. 再交代一件小事，說「換手」，看過內容再說「確認」。開新對話貼上接續指令，接得下去才算通過。

| 沒通過的情形 | 處理 |
| :-- | :-- |
| 不知道什麼是開工 | 確認資料夾相同；輸入「請讀 AGENTS.md，然後開工」；Claude Code 再確認 CLAUDE.md 存在 |
| 進度說錯 | 看 HANDOFF.md 最上面那則是否有更新 |
| 換手後接不上 | 檢查便條是否寫到「沒看過對話也看得懂」，接續指令有沒有寫要讀的檔案 |
| 沒問確認就改便條 | 把該條規則加上「絕對要等我說確認」，再測一次 |

### 1.8 選配：兩種工具共用 Skill

第一級的「開工／換手／收工」直接由 AGENTS.md 說明，不依賴 Skill。沒有既有 Skill 的人先略過，不為湊流程自動安裝或產生 Skill。

有需要時依第 6 節設定：確認專案中的共用 Skill 正本，讓 Codex 與 Claude Code 的本機入口連到它；Windows 用 Junction、Mac 用符號連結。這是另外授權的本機設定，各台電腦各做一次。

## 2. 第二級：多台電腦接力

**目標**：多台電腦輪流工作時，進度會同步，也知道誰正在用。Git 像有紀錄的整批交貨單，每一批都知道改了什麼，也能找回舊版。

### 2.1 先決條件（任一項不成立就停）

1. 第一級已通過驗收。
2. 使用者明確回答「機關允許，而且這個資料夾的內容適合放上 GitHub」。回答不確定時，建議先問資訊單位，停在這裡。
3. 資料夾不在 OneDrive、Google 雲端硬碟、iCloud、Dropbox 的同步位置。路徑看不出來就問。若在裡面，說明原因與搬移方案，不自行搬。

### 2.2 工具檢查

| 檢查 | 指令 | 找不到時 |
| :-- | :-- | :-- |
| Git | `git --version` | 先查常見安裝位置；仍沒有才建議從 git-scm.com 安裝 |
| GitHub CLI | `gh --version` | 先查常見安裝位置；仍沒有才建議從 cli.github.com 安裝 |
| 登入 | `gh auth status` | 請使用者自己執行 `gh auth login`，再檢查一次 |

`gh auth status` 的輸出若含權杖，不要轉貼。確認登入帳號後，唸出帳號名稱請使用者確認。

### 2.3 儲存庫狀態

先執行 `git rev-parse --show-toplevel`：

| 結果 | 處理 |
| :-- | :-- |
| 不是儲存庫 | 同意後 `git init -b main` |
| 就是這個資料夾 | 列出 `git status -sb`、`git remote -v`，不重新初始化 |
| 已有提交歷史或遠端 | 停下說明：上傳會送出全部舊歷史，包含以前刪掉的檔案。預設建議改用全新資料夾；要沿用，必須先檢查全部歷史、實際分支名稱，並確認遠端是使用者自己的且為 `PRIVATE` |
| 是上層資料夾 | 停止，說明會把其他檔案混進來 |

需要姓名與信箱時，只設在這個儲存庫（`git config user.name`、`git config user.email`，不加 `--global`）。建議使用 GitHub 的隱私信箱，由使用者決定。

### 2.4 防護檔

`.gitignore` 是「不要放進交貨單」的清單。已有就只補缺少的：

```gitignore
.env
.env.*
!.env.example
*.key
*.pem
*.p12
*.pfx
*.ppk
*.env
id_rsa*
id_ed25519*
*credentials*
secrets*
node_modules/
*.tmp
*.bak*
.claude/settings.local.json
LOCAL-ONLY.md
```

`.gitattributes` 減少 Windows 與 Mac 換行差異：

```gitattributes
* text=auto eol=lf
```

資料夾裡若有上述類型的檔案，用 `git -c core.quotepath=false check-ignore <檔名>` 確認真的有擋住。已被 Git 追蹤的檔案不受 `.gitignore` 影響，要用 `git ls-files` 另外檢查。

### 2.5 第一批清單與掃描

列出每個預計提交的檔案與大小，再檢查：

1. 檔名：密碼、金鑰、憑證、`.env`，以及含 token、secret 的檔名；命中就預設排除，使用者同意才放。
2. 內容：像金鑰的長字串、身分證字號、電話、電子郵件、內部網址。只回報檔名與行號，不印出內容；命中就預設排除，使用者同意才放。再用 `git -c core.quotepath=false status --ignored -s` 列出被擋掉的檔名，正常檔案被誤擋就問使用者。Word、Excel、PDF、圖片、壓縮檔這類無法可靠掃描內容的檔案，另列「未掃描」請使用者逐一確認，不得說已通過。
3. 大小：單檔超過 50 MB 先排除，改放機關允許的儲存空間，旁邊放 `MEDIA.md` 記位置。
4. 檔名相容：避免 `: * ? " < > |`；有捷徑或符號連結就列出來問。

使用者確認清單後：

```text
git add -- <檔案1> <檔案2>
git -c core.quotepath=false diff --cached --name-status
git commit -m "建立 AI 交接簿"
```

暫存清單和確認過的清單不同就停止。中文檔名若顯示成亂碼，所有列清單的指令改用 `git -c core.quotepath=false …`（例如 `git -c core.quotepath=false status -sb`）。

### 2.6 建立私人儲存庫並推送

1. 問名稱（預設用資料夾英文名，或 `my-ai-handoff`）。用 `gh repo view <帳號>/<名稱>` 檢查是否已存在；存在就停下來問，不沿用。
2. 取得同意後：`gh repo create <帳號>/<名稱> --private --source=. --remote=origin`。
3. 推送前確認：`gh repo view <帳號>/<名稱> --json nameWithOwner,visibility`。帳號要正確，`visibility` 要是 `PRIVATE`，不符就停止。
4. `git push -u origin main`。
5. `git status -sb` 沒有 `ahead` 才算推送完成。

### 2.7 本機卡與簽到表

取得電腦名稱：Windows `$env:COMPUTERNAME`，Mac `scutil --get LocalHostName`。問使用者怎麼稱呼這台（預設 `office` 或 `home`），建立 `machines/<稱呼>.md`：

```markdown
# 本機卡：<稱呼>

只有這台電腦可以修改本檔。

- 電腦名稱：
- 交接簿資料夾路徑：
- 已安裝工具：
- 大檔存放位置：
- 注意事項：
```

不寫密碼、憑證、內部網址。共用規則不寫死路徑，路徑一律查本機卡。

在 `HANDOFF.md` 標題下方加入，每台一行，只改自己那行；原有便條全部保留在下面：

```markdown
## 簽到表

- <稱呼>：已收工｜<AI 工具>｜YYYY-MM-DD HH:MM
```

狀態只有「工作中」和「已收工」。其他電腦加入時，各自加一行。

### 2.8 升級三個口令

先說明並取得同意：

1. 「開工」會自動提交並推送 `HANDOFF.md` 一個檔案，讓另一台看得到誰在用。不同意就改成每次詢問，把結果寫進開工第 6 步的「授權」。
2. 「換手」會建立 `daily/` 日誌資料夾。

再分三步改 `AGENTS.md`，改前備份（檔名加 `.bak-YYYYMMDD-HHMM`，已被 `.gitignore` 排除）並顯示差異：

1. 從「交接規則」刪除「開工」「換手」「收工」三條，其餘留在原處。既有舊版的「抓最新」「存檔上傳」「同步規則」也一併刪除。
2. 把「更新便條時」那條改成：`- 更新便條時，新的放在簽到表之下、舊便條之上，舊的保留。每則寫日期時間、機器・AI 工具、做完、下次接手、只跟這台有關、請另一台處理。`
3. 把下列內容加在檔案最後，`<分支>` 換成實際名稱：

```markdown
## 接力規則

### 開工
1. git fsck --no-dangling，有錯就停止並回報。
2. 做「看改動」，換手紀錄看最新的 daily 裡這台的「換手」段落。
3. 做「更新」。連不上就停，不用舊簽到表判斷。若只有這台的簽到提交沒推送，我同意就補推，跳到第 7 步。
4. 用電腦名稱比對 machines/。對不上就問我是哪台；我同意才新增本機卡與簽到行（先寫「已收工」），照「上傳」第 1～8 步處理這兩個檔案（不寫便條）。
5. 看簽到表：
   - 別台「工作中」：讓我選先回那台收工、先做別的（這兩種都不簽到，停在這裡）、或知道風險照樣開工。
   - 這台「工作中」，且有不早於簽到時間的換手：接續，跳到第 7 步。
   - 這台「工作中」，便條標「尚未上傳」：不重新簽到，照「看改動」第 3 步問過後跳到第 7 步。
   - 這台「工作中」，其他情形：問我另一個對話或工具是否還在做。
6. 簽到：HANDOFF.md 沒有其他改動、暫存區是空的，才只改這台那行並只提交這個檔案；確認只會送出這一個提交才推送。失敗要告訴我。授權：<已同意直接推送／每次先問>。
7. 讀 HANDOFF.md 與較新的 daily，用三句話說明上次做到哪、下一步、要注意什麼，等我指示。

### 換手
1. 停在安全點，關掉自己開的背景工作。
2. 列出做完、決定與理由、待確認、下一步、相關檔案、所有未提交的改動。
3. 等我說「確認」，才寫進 daily/YYYY-MM-DD.md，標題寫時間、機器・AI 工具與「換手」。
4. 給我一段貼到新對話的接續指令：要讀哪些檔案、未提交的改動請保留、先回報狀態再動手。
5. 不改簽到表、不提交、不推送。

### 收工
1. 做「看改動」，加上 daily 的換手段落。
2. git fetch。失敗就是離線：我確認後只寫便條並標「尚未上傳」，不簽退、不提交，到此為止。
3. 遠端較新就停，照「兩邊都有新內容」。
4. 做「上傳」；第 6 步寫便條時，同時把這台那行改成「已收工」。
5. 列出仍未提交的檔案，再回報完成。

### 看改動
1. 用 git -c core.quotepath=false status -s 列出未提交的改動。
2. 讀最近的換手紀錄與 LOCAL-ONLY.md（有才讀）。裡面列的檔案、換手紀錄本身都算已知，原地保留，不 stash、不還原。
3. 便條標「尚未上傳」：問我要先補做收工，還是接著做。
4. 其他改動先問我。

### 更新
1. git fetch。失敗就告訴我，不當成已是最新。
2. 只落後：git pull --ff-only。
3. 只有本機有未推送的提交：列出來問我。
4. 兩邊都有新提交，或更新被擋：停，照「兩邊都有新內容」。
5. 更新後 AGENTS.md 有變：重讀，從開工第 1 步重來。

### 上傳
1. 列出要提交的檔案，再用 git -c core.quotepath=false log --name-status origin/<分支>..HEAD 列出未推送的提交，後來刪掉的檔案也要列。
2. 用 git -c core.quotepath=false status --ignored -s 列出被擋掉的檔名，問我有沒有誤擋。
3. 檢查機密、個資、超過 50 MB。無法掃描內容的檔案列為「未掃描」。
4. 不上傳的檔案記進 LOCAL-ONLY.md（不提交）。未推送的提交裡有不能上傳的內容，停止並問我。
5. 把清單、檢查結果、便條內容給我看，等我說「確認」。
6. 寫便條，逐一 git add，核對暫存清單後提交。
7. 再看一次未推送的提交，和我確認過的相同才推送。失敗要告訴我。
8. git status -sb 確認與遠端分支一致。

### 兩邊都有新內容
1. 停下，不 rebase、不 stash、不強推，告訴我兩邊各改了什麼。
2. 我同意才照建置包「兩邊都有新內容時」一節：https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md
3. 讀不到或沒有這一節就停止，請我提供檔案。

### 界線
- 只改自己這台的 machines/ 檔案與簽到行；看到另一台的設定變動，不跟著搬資料夾或安裝軟體。
- 同一台電腦不讓兩種 AI 同時改檔案。
- 有衝突先列差異，不擅自覆蓋；兩邊各自新增的紀錄都保留。
- 不把這個資料夾放進雲端同步資料夾。
```

改完讀回，確認「開工」「換手」「收工」各只有一份，原有的其他規則還在。接著依 2.5 確認清單，提交推送。

### 2.9 其他電腦加入

1. 第一台先「收工」，確認遠端已有要讓另一台接手的版本。
2. 在第一台依 2.10 產生已填好 repo 網址的「新電腦接續指令」。
3. 到另一台貼該指令，依第 3 節完成首次下載、開啟資料夾、讀回規則、補齊本機設定與驗收。**沒有交接簿資料夾時，要先下載，不能直接說「開工」。**已有正確 repo 的電腦，說「開工」就會更新並重讀規則。
4. 新增的電腦建立自己的本機卡與簽到行，不改別台的；新機取代舊機時，先請使用者確認沿用哪個角色，舊機停止使用後才更新該角色卡並保留換機紀錄。不得把新電腦猜成另一台。
5. 有選配 Skill 才依第 6 節接回入口。開工簽到的授權沿用既有設定；沒有記錄就先確認。

軟體、登入狀態、金鑰不會跟著過來，要在每台各自處理。

### 2.10 產生「新電腦接續指令」

第一台完成 2.8 並上傳後，就先產生接續卡，此時第二級標「已建立、待驗收」；2.11 通過後更新驗收欄，接入資訊有變時也更新。讀取目前 repo 的實際網址與分支，請使用者確認後填入，不猜名稱，也不放含憑證的網址。資訊未確認就保留待填欄位，不宣稱可直接接入。

將以下「接續卡」與完整可複製的自然語言指令交給使用者；存入專案的 `新電腦接續指令.md` 前先取得同意，之後依清單確認流程提交推送，讓另一台能查閱。

| 接續卡欄位 | 填寫方式 |
| :-- | :-- |
| 我的 repo 網址 | 實際 GitHub repo 網址，非本建置包公開 repo |
| 工作分支 | 實際使用分支，不假設一定叫 main |
| 已建立／已驗收級別 | 分別記錄，不能把建檔當通過驗收 |
| 規則與便條位置 | repo 內相對路徑 |
| 筆記與 Skill 正本 | 只記實際存在者；未選配就寫未設定 |
| 最近一次已推送版本 | 真正已上傳的 commit；卡片本身稍後提交時，不預填尚未存在的新 commit |
| 大檔與本機事項 | 有 MEDIA.md 就指向它；登入、金鑰與軟體需另處理 |

接續指令使用首頁「新電腦首次接入」範本，把自己的 repo 網址、分支與上述相對路徑填好，再加一句「完成第 3 節後，若原級別仍待驗收，依該級驗收步驟測完；通過後按原級別接續，不重建或自動升級」。本機下載位置留到新電腦詢問，不能沿用第一台的磁碟路徑。

### 2.11 驗收

前提：另一台已依第 3 節下載並完成接入。以下測的是日常使用，不是第一次下載。

1. 第一台「開工」，做一件小事，「收工」、看清單、「確認」。第二台「開工」，看得到成果，也說得出進度。
2. 第二台還在工作中時，第一台說「開工」，會提醒你並讓你選；先不要選照樣開工。
3. 第二台「換手」並「確認」，開新對話貼上接續指令，能接著做；再開一個新對話只說「開工」，也說得出換手的進度。
4. 第二台「收工」並「確認」，第一台「開工」看得到；第一台再「收工」並「確認」，簽到表兩台都是「已收工」。

| 沒通過的情形 | 處理 |
| :-- | :-- |
| 無法快轉（Not possible to fast-forward） | 兩邊都有新提交，依 4.1 處理，不強制覆蓋 |
| 推送被拒 | 先 `git fetch`；另一台較新就依 4.1 處理 |
| 沒有權限 | 檢查登入帳號是否正確 |
| 看不到工作中 | 檢查另一台的簽到有沒有推送成功 |
| 忘記收工 | 簽到表只能提醒。先回那台收工；回不去就列出風險讓使用者選 |
| 新對話接不上 | 檢查日誌是否寫到「沒看過對話也看得懂」 |

## 3. 新電腦／已有資料夾接入既有交接簿

這是接回既有級別的流程，不是另一個級別。參考「首次下載 → 讀回規則與記錄 → 接上本機入口 → 驗收」的換機邏輯。用到的資料夾名稱、路徑與功能，一律以下載後實際存在的內容為準，不把本建置包的範例硬套成每個人的專案。

### 3.1 第一台先準備

- 若第一台還能使用，先整理交接並確認上傳完成。只有第一級、沒有遠端時，回第一台完成第二級，不能在第二台假裝有資料可下載。
- 若舊機已壞，只能先接回遠端已保存的版本；明確列出其日期與 commit，不宣稱是損壞前的最新進度。
- 準備第 2.10 節接續卡；沒有卡也能接入，但要先問使用者自己的 repo 網址，不使用說明書的 repo 代替。

### 3.2 檢查新電腦與確認下載位置

1. 依 2.2 檢查 Git、gh 與登入；若帳號不是 repo 擁有者，確認此帳號確有存取授權。登入由本人完成，不收帳密。
2. 唸出 repo 擁有者、名稱，查證權限與可見性。沒有權限就停；本流程不建立新遠端，也不改現有遠端。
3. 問本機存放位置，不選雲端同步位置、家目錄、桌面或磁碟根目錄；說明完整目的路徑。
4. 目的資料夾已存在時，不覆蓋、不刪除、不在其中重新初始化。若是正確 repo，改走 3.5；否則請使用者換空位置。

### 3.3 首次下載並開啟

確認後以實際值執行，尖括號內容先替換，整個路徑以引號保護：

```text
gh repo clone "<自己的 repo 網址>" "<新電腦的完整目的路徑>"
```

確認下載成功、repo 根目錄與遠端符合使用者選擇，再確認工作分支；接續卡指定的分支不是預設分支時，說明差異、確認後再切換，不在不明狀態下改分支。

請使用者用 AI Agent 開啟這個下載完成的資料夾；新對話先明確要求讀取裡面的規則。工具若能安全切換工作目錄，可切換後重新確認路徑，不能還在接入用空資料夾就假稱已載入規則。

需要改開專案或新對話時，AI 必須提供一段已填好實際資訊的後續指令，避免使用者只說「開工」而跳過未完成的本機設定：

```text
這是新電腦首次接入的「下載後續」，請不要重新下載或重建。
我已下載自己的 repo：〈實際 repo 網址〉
目前資料夾應是：〈這台的完整路徑〉，工作分支：〈實際分支〉。
原本已建立／已驗收的級別：〈分別填寫〉；尚未完成的本機設定：〈列出〉。

請先確認目前路徑，再讀這裡的 AGENTS.md、CLAUDE.md 與其中指定的交接紀錄。依 AI 交接簿建置包 0.3 的 3.4～3.6 節繼續補設定與驗收，不自動升級。
建置包：https://raw.githubusercontent.com/vm3vup54/slides/main/2026-11-ai-handoff-kit/AI-HANDOFF-KIT.md
若拿到的版本較舊或讀不到，請我提供下載的建置包，不自行猜。驗收完成後才按原級別開工。
```

### 3.4 讀回工作脈絡、補本機設定

1. 先讀根目錄 AGENTS.md 與 CLAUDE.md（如果有），從其中找到 HANDOFF、筆記、日誌與 Skill 的實際相對路徑。只讀存在且非機密的紀錄；沒有 MEMORY.md 等檔案屬正常，不憑空建記憶。
2. 確認原級別與前次驗收紀錄。既有資料不是本建置包格式時，先依其規則說明差異，不覆寫成模板。若尚未驗收，列出待驗項目，不自動升級。
3. 讀最新交接與必要日誌，先說出可恢復的版本、上次進度與下一步。已完成第二級時先看另一台是否工作中，有風險就依既有規則讓使用者選。
4. 規則共讀依 1.4 檢查，不把原有 CLAUDE.md 的其他內容刪掉。有已選配的共用 Skill 時依第 6 節接回；Windows／Mac 入口必須指向這台的路徑，不照搬另一台的絕對路徑。
5. 第二級才登記本機卡。新增機器建立自己的卡；取代舊機先確認角色與舊機停用，再更新對應卡。第一級不增設本機卡。登記後，依規則的「上傳」提交推送本機卡與簽到行。
   - 第二級依 2.3 在這個儲存庫設定 Git 姓名與信箱；下載時不會帶過來。
6. 列出不能跟 Git 下載的項目：軟體、登入、金鑰、憑證、被排除的檔案、大檔或外部服務開通。依實際需要列缺口，不收秘密值、不宣稱已恢復聊天紀錄或全部記憶。

### 3.5 已有資料夾：檢查後才更新

確認 repo 根目錄與遠端正確，先看 `git status -sb` 與 `git fsck --no-dangling`。有不明改動或 Git 健康錯誤就停下來列出狀況。

再 `git fetch origin`，確認目前分支與追蹤分支。只有單純落後、工作區可安全更新時才 `git pull --ff-only`；已最新就略過，僅本機超前就回報未上傳進度。兩邊都有提交、衝突或分支不明時不強制處理。更新後回到 3.4 讀規則、補設定。

### 3.6 接入驗收與日常使用

1. **檔案正確**：完整路徑、遠端、分支與版本符合接續卡或使用者確認；規則與最新交接實際存在。
2. **規則與 Skill 接上**：在實際使用的工具開新對話，確認能說出一項既有規則。若兩工具都裝了，各驗一次；有選配 Skill 才確認兩邊都能找到指定 Skill，沒有裝另一工具就標示那邊未驗證。
3. **進度接上**：能說出上次做完、下一步與未恢復的本機項目，並與交接檔核對。只看到檔案不算完成。
4. 第二級日常依接回的開工／收工規則使用，更新與上傳都包在裡面；第一級若只是本機複製接入，沒有遠端同步功能。
5. 驗收不通過就回報卡在哪一步；已建立、已下載、已驗收與尚缺項目分別列清楚。恢復到已知安全狀態，不覆蓋或強制重建。

## 4. 復原與意外

| 情形 | 處理 |
| :-- | :-- |
| 想取消第一級 | 有備份就還原；沒有備份的檔案由使用者決定是否移除 |
| 想回到舊版 | `git log --oneline` 找版本，說明差異，用新的提交還原 |
| 兩邊都有改、推送被拒 | 依 4.1 處理 |
| `git fsck` 有錯 | 停止抓取與推送，先備份整個資料夾，再討論修復 |
| 機密已提交、未推送 | 停止推送，告訴使用者，討論後再處理歷史 |
| 機密已推送 | 立即告知。先作廢或更換該金鑰，並通報機關資安單位；只加 `.gitignore` 不夠 |

### 4.1 兩邊都有新內容時

像兩個人各寫了一份筆記，要合成一份。先用白話說明，每一步都等使用者同意：

1. 把整個資料夾備份到外面的位置（不要放進同步資料夾），確認備份讀得到。
2. `git fetch`，白話列出兩邊各改了什麼。再用 `git -c core.quotepath=false log --name-status origin/<分支>..HEAD` 逐一列出本機未推送的提交，後來刪掉的檔案也要列，依 2.5 檢查；有不能上傳的內容就停止，不合併也不推送。
3. 有未提交的改動時，依 2.5 掃描並確認清單，先在本機提交，不推送。
4. 只有本機有新提交，就不用合併，依收工確認後推送；只是落後，就 `git pull --ff-only`。兩邊都有提交，執行 `git merge --no-commit --no-ff origin/<分支>`。
5. 有衝突時：便條、日誌兩邊都保留，依時間排列；簽到表各台用自己那行的最新狀態；其他檔案逐一請使用者選。
6. 讀回檔案，確認沒有衝突記號、沒有少掉任何一邊的內容。解完的檔案逐一 `git add -- <檔案>`，看過暫存清單，給使用者看結果，同意後才提交。推送前再看一次未推送的提交，和確認過的相同才推送；AGENTS.md 有變就重讀。
7. 合併提交前想放棄，執行 `git merge --abort`。推送又被拒就從第 2 步再來一次，仍不行就停止回報。

## 5. 限制

- 寫進規則不保證 AI 每次都照做，重要動作由人確認。
- GitHub 不是完整備份：未提交、被排除、太大的檔案都不在上面。
- 各工具讀取規則的方式可能改版，以官方文件為準。
- 本版尚未在所有電腦與 AI 工具上實測。

## 6. 選配附錄：共用 Skill 正本與兩種工具入口

### 6.1 先確認正本與範圍

問使用者要共用哪些既有 Skill。選一個專案內的正本資料夾，例如 `skills/`；若既有規則使用 `000_Agent/skills/`，沿用它，不另養一份。每個 Skill 是一個子資料夾，內有 SKILL.md。沒有 Skill 就跳過，不自動安裝。

```text
專案／skills／my-skill／SKILL.md  ← 唯一正本
       ↑                       ↑
~/.agents/skills/my-skill   ~/.claude/skills/my-skill
       Codex 入口             Claude Code 入口
```

以下是「使用者層級」入口，可能在其他專案也看得到這些 Skill；先說明範圍並取得同意。預設逐個 Skill 加連結，保留兩個入口裡其他已安裝的 Skill，不整包替換。已有整個 skills 入口連結且已指向正確正本時，可驗證後沿用，不再建立巢狀重複連結。

### 6.2 建立連結之前

1. 確認工具已安裝、共用正本內有欲用 Skill 的 SKILL.md，問清楚正本的完整本機路徑。
2. 確認家目錄下兩個入口的狀態：不存在、實體資料夾、或既有連結。已有連結要讀取實際指向，確認可存取。
3. 指定 Skill 的入口已存在時：若已指向同一正本，略過；否則列出差異，備份後由使用者選擇，不刪除、不覆蓋。修改既有連結前也要備份可復原的指向記錄。同名的空資料夾也算已存在，一樣先停下來問。
   - 兩個 `skills` 入口整包都是連結時，先解析到最終位置。若指向同一個資料夾，逐個新增會寫進那個資料夾，第二個也會失敗，所以不要執行 6.3／6.4：該處就是正確正本時，驗證後直接沿用；不是時，先說明差異再問使用者。
4. 說明 Windows 用 Junction、Mac 用符號連結，展示本機實際指令，確認後才執行。不把這台的絕對路徑或入口連結當成可直接移到另一台的設定。

### 6.3 Windows 範例（PowerShell）

這段只示範新增一個名為 my-skill 的入口；正本路徑換成自己的，且必須先通過 6.2，確認兩個同名目的入口均不存在：

```powershell
$skillSource = "D:\my-ai-handoff\skills\my-skill"
$codexSkillRoot = Join-Path $HOME ".agents\skills"
$claudeSkillRoot = Join-Path $HOME ".claude\skills"
New-Item -ItemType Directory -Force -Path $codexSkillRoot, $claudeSkillRoot | Out-Null
New-Item -ItemType Junction -Path (Join-Path $codexSkillRoot "my-skill") -Target $skillSource
New-Item -ItemType Junction -Path (Join-Path $claudeSkillRoot "my-skill") -Target $skillSource
Get-Item (Join-Path $codexSkillRoot "my-skill"), (Join-Path $claudeSkillRoot "my-skill") | Select-Object FullName, LinkType, Target
```

### 6.4 Mac 範例（zsh）

同樣先通過 6.2，確認正本與不存在的目的入口；不是 Windows 指令換斜線就能用：

```sh
skill_source="$HOME/my-ai-handoff/skills/my-skill"
mkdir -p "$HOME/.agents/skills" "$HOME/.claude/skills"
ln -s "$skill_source" "$HOME/.agents/skills/my-skill"
ln -s "$skill_source" "$HOME/.claude/skills/my-skill"
readlink "$HOME/.agents/skills/my-skill"
readlink "$HOME/.claude/skills/my-skill"
```

### 6.5 驗收與復原

- 讀回兩個入口的實際指向，解析成完整路徑，確認都指向同一個 Skill 正本，且能讀到其中的 SKILL.md。
- 在已安裝的 Codex／Claude Code 各開新對話，查看 Skill 清單或明確要求使用該 Skill；工具尚未辨識到時，先確認位置與版本，必要時重開，不只憑連結存在就說可用了。
- 工具專屬參數或外部依賴不保證跨工具可用，另列未驗證項目。
- 換電腦後先下載正本，再以新電腦路徑重建本機入口；Git 不會代替這一步。
- 想取消時，先展示「僅移除這次新增的入口連結、不動正本」的方案，經確認才處理；若先前保留過舊入口，依備份指向還原，不自動刪檔。
